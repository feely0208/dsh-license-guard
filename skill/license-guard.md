# 开源许可合规检查

发布前、开源前、被审计或尽调时，扫一遍依赖树，找出**许可不合规**的包。

## 一、何时用

- 发布产物前（打包进产物 = 分发，GPL 义务从此触发）
- 开源前、把仓库转公开前
- 客户审计 / 投资尽调 / 上级检查问到「你用了什么开源代码」
- 引入新依赖后

## 二、它查什么

| 级别 | 查什么 |
|---|---|
| 🔴 高 | **GPL / AGPL** —— 强传染，分发时可能要求你开放自己的代码；AGPL 还覆盖网络服务 |
| 🟡 中 | **许可未知** —— 「没写许可证」≠「可以随便用」，法律默认是「保留所有权利」 |
| 🟡 中 | 项目自身**缺 LICENSE 文件** |
| 🟢 低 | **LGPL / MPL / EPL** —— 仅修改该库本身时有义务 |
| 🟢 低 | package.json **缺 license 字段** |

## 三、怎么用

```bash
<cli 路径>                 # 扫当前目录
<cli 路径> --demo          # 用内置样本看检出效果
<cli 路径> --html r.html   # 输出 HTML 报告（可截图存档）
<cli 路径> --json          # 给 CI 二次处理
```

**退出码 1 = 有高危命中**，可直接挂 CI 卡口。

## 四、判据来源

每条规则都带 `source`，指向具体条款：

- GPL-2.0/3.0 §5、AGPL-3.0 §13 —— 分发衍生作品时须以同许可开放源代码
- LGPL-3.0 §4、MPL-2.0 §3.3 —— 仅修改该库本身时触发
- 著作权法默认规则 —— 未声明许可 = 保留所有权利

## 五、边界

**GPL 义务是否触发，取决于「你有没有分发」。** 本工具只能告诉你**依赖里有 GPL**，
不能替你判断你的分发场景是否构成「分发」—— 那需要结合你的产品形态判断。

另：**依赖的许可证字段可能不准**（维护者写错、或用了自定义协议）。
本工具读的是 lockfile / package.json 里的声明值，**不校验其真实性**。
对高风险的包，建议到上游仓库核对。

## 六、覆盖面

5 条规则，覆盖依赖树的许可风险 + 项目自身的基础文件。
**不覆盖**：专利条款、商标、出口管制、SSPL/BUSL 等非 SPDX 自定义协议。
